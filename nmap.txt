🔹 Theory Summary
🔸 Version Control System (VCS)
A Version Control System helps track file changes over time so that you can restore previous versions, collaborate with others, and manage project history efficiently.
•	Local VCS: Tracks files only on one system.
•	Centralized VCS: Uses one central server (e.g., SVN).
•	Distributed VCS (DVCS): Every user has a full copy of the repo (e.g., Git).
________________________________________
🔸 Git
Git is a distributed version control system that tracks code changes locally.
It allows developers to work independently and merge their work seamlessly.
🔸 GitHub
GitHub is a remote hosting platform for Git repositories — used for collaboration, synchronization, and backup of code.
________________________________________
🔸 Key Git Concepts
Term	Meaning
Repository (Repo)	The project directory where Git tracks changes.
Commit	A snapshot of the project at a point in time.
Branch	A separate line of development.
Merge	Combines changes from different branches.
Remote	Online repository hosted on GitHub.

Experiment 3: Create Jenkins Pipeline using Scripted/Declarative Pipeline
Step 1: Open Jenkins Dashboard
•	Go to your browser → open http://localhost:8080
•	Log in with your Jenkins admin username and password.
________________________________________
Step 2: Create a New Pipeline Project
1.	Click “New Item” on the left menu.
2.	Enter a name → MyFirstPipeline.
3.	Select “Pipeline” → click OK.
________________________________________
Step 3: Scroll Down to the Pipeline Section
•	Under Definition, choose “Pipeline script” (default option).
•	You’ll see a big text box to write your pipeline code.
________________________________________
Step 4: Write Declarative Pipeline Code
Copy and paste the following inside the script box:
pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                echo '🔨 Building the project...'
            }
        }
        stage('Test') {
            steps {
                echo '🧪 Running tests...'
            }
        }
        stage('Deploy') {
            steps {
                echo '🚀 Deploying the application...'
            }
        }
    }
}
________________________________________
Step 5: Save and Run
1.	Click Save.
2.	On the left sidebar → click Build Now.
✅ Jenkins will start running your pipeline.
________________________________________
Step 6: View Console Output
1.	Click on the #1 build under “Build History”.
2.	Click Console Output.
You’ll see:
[Pipeline] Start of Pipeline
🔨 Building the project...
🧪 Running tests...
🚀 Deploying the application...
Finished: SUCCESS
✅ This confirms your Declarative Pipeline ran successfully.
________________________________________
Step 7: Run a Scripted Pipeline
Now, to understand the difference — edit your pipeline:
1.	Go to Dashboard → MyFirstPipeline → Configure.
2.	Scroll to the Pipeline section.
3.	Replace the code with:
node {
    stage('Build') {
        echo '🔧 Building the project...'
    }
    stage('Test') {
        echo '🧩 Testing the project...'
    }
    stage('Deploy') {
        echo '🚢 Deploying the project...'
    }
}
4.	Click Save → Build Now again.
________________________________________
Step 8: Check Scripted Pipeline Output
In Console Output, you’ll see:
🔧 Building the project...
🧩 Testing the project...
🚢 Deploying the project...
Finished: SUCCESS
✅ This confirms your Scripted Pipeline also ran successfully.
________________________________________
Step 9: Compare Results

Scripted	Groovy script style	node {}	More flexible

Introduction to Jenkins
Jenkins is an open-source automation server that helps in implementing Continuous Integration (CI) and Continuous Deployment (CD). It automates repetitive tasks such as building, testing, and deploying applications, ensuring faster software delivery with fewer errors.
A pipeline in Jenkins represents a sequence of automated steps that run from code development to deployment. Pipelines are written using a Jenkinsfile which defines the stages, steps, and actions.
________________________________________
🔹 Types of Jenkins Pipelines
There are mainly two types of pipelines in Jenkins:
1. Declarative Pipeline
•	Introduced to make pipeline syntax simpler and more readable.
•	Uses the keyword pipeline {} as the root.
•	The structure is predefined, making it less error-prone.
•	Best for beginners or standard CI/CD processes.
________________________________________
2. Scripted Pipeline
•	Based on Groovy scripting and provides more flexibility.
•	Uses the node {} syntax.
•	Allows complex logic, loops, conditionals, and external integrations.
•	Preferred by advanced users for custom automation.


🔹 Key Components of a Jenkins Pipeline
Component	Description
Agent	Defines where the pipeline runs (local machine or remote node).
Stages	Logical divisions like Build, Test, Deploy.
Steps	Actual tasks performed within a stage.
Post	Actions to run after completion (like cleanup or notifications).
________________________________________
🔹 Advantages of Jenkins Pipelines
1.	Automation: Reduces manual tasks by automating build, test, and deployment.
2.	Consistency: Ensures uniform workflow across environments.
3.	Error Reduction: Detects issues early in the development lifecycle.
4.	Scalability: Supports integration with multiple tools (Git, Maven, Docker).
5.	Flexibility: Scripted pipelines allow dynamic customization.
________________________________________
🔹 Difference Between Declarative and Scripted Pipelines
Feature	Declarative	Scripted
Syntax	Simplified, structured (pipeline {})	Groovy-based (node {})
Ease of Use	Beginner-friendly	Complex but flexible
Validation	Strict syntax rules	Free-form scripting
Error Handling	Automatic validation	Manual error control
Best For	Standard CI/CD setups	Custom automation logic
________________________________________
🔹 Conclusion
Jenkins Pipelines help automate software development workflows efficiently.
The Declarative Pipeline is easy to use and ideal for beginners, while the Scripted Pipeline provides greater control for complex automation scenarios.

Experiment 5: Docker Architecture, Container Lifecycle, and Custom Image
________________________________________
🎯 Aim
To understand Docker architecture and container lifecycle, install Docker, execute Docker commands to manage images and containers, create a custom Docker image using a Dockerfile, and upload it to Docker Hub.
________________________________________
🧠 Step 1: Understand Docker Architecture
Before starting, understand these 3 main components of Docker:
Component	Description
Docker Client	Command-line tool you use (docker run, docker ps, etc.).
Docker Daemon (Server)	Background service that builds, runs, and manages containers.
Docker Image	Template used to create containers (like an app snapshot).
Docker Container	Running instance of an image (lightweight & isolated).
Docker Hub	Cloud registry for storing and sharing Docker images.
Architecture Flow:
Docker Client → Docker Daemon → Containers & Images → Docker Hub (Registry)
________________________________________
⚙️ Step 2: Install Docker
On Windows:
1.	Download Docker Desktop for Windows → https://www.docker.com/products/docker-desktop
2.	Install it.
3.	After installation, open Docker Desktop and ensure it says “Docker is running”.
4.	Open PowerShell or Command Prompt and check:
5.	docker --version
6.	docker info
✅ Output shows Docker client and server details.
________________________________________
🧱 Step 3: Basic Docker Commands
Let’s get comfortable using Docker commands.
Command	Purpose
docker pull ubuntu	Download an image from Docker Hub
docker images	List all images on your system
docker run -it ubuntu	Run a container interactively
docker ps	List running containers
docker ps -a	List all containers (even stopped ones)
docker stop <container_id>	Stop a running container
docker rm <container_id>	Remove a container
docker rmi <image_id>	Remove an image
docker exec -it <container_id> bash	Access a running container
Example:
docker pull hello-world
docker run hello-world
✅ You’ll see a message that confirms Docker works correctly.
________________________________________
🧩 Step 4: Create a Custom Docker Image
Now we’ll make our own image using a Dockerfile.
(a) Create a project folder
mkdir MyDockerApp
cd MyDockerApp
(b) Create an index.html
<!DOCTYPE html>
<html>
  <body>
    <h2>Hello from My Custom Docker Image!</h2>
  </body>
</html>
(c) Create a Dockerfile
# Step 1: Use an official Nginx base image
FROM nginx:latest

# Step 2: Copy our web file into the container
COPY index.html /usr/share/nginx/html/index.html

# Step 3: Expose port 80
EXPOSE 80
________________________________________
🏗️ Step 5: Build the Image
In PowerShell (inside your project folder):
docker build -t mydockerapp:v1 .
✅ This builds a custom image named mydockerapp with version v1.
Check it:
docker images
________________________________________
▶️ Step 6: Run the Container
docker run -d -p 8080:80 mydockerapp:v1
✅ Open browser → http://localhost:8080
You’ll see your custom HTML message.
Check running containers:
docker ps
Stop it later:
docker stop <container_id>
________________________________________
☁️ Step 7: Push Image to Docker Hub
(a) Create a Docker Hub account
Go to → https://hub.docker.com
(b) Login via terminal
docker login
Enter your Docker Hub username and password.
(c) Tag your image (Docker Hub requires username prefix)
docker tag mydockerapp:v1 your_dockerhub_username/mydockerapp:v1
(d) Push it
docker push your_dockerhub_username/mydockerapp:v1
✅ Go to Docker Hub → You’ll see your uploaded image.
________________________________________
🔁 Step 8: Container Lifecycle Summary
Stage	Command Example	Description
Create	docker create	Defines a container from an image
Start	docker start	Starts a stopped container
Run	docker run	Creates + starts together
Pause	docker pause	Temporarily suspends
Stop	docker stop	Gracefully stops
Restart	docker restart	Restarts container
Remove	docker rm	Deletes container
________________________________________
🧾 Step 9: Conclusion
✅ Docker simplifies application deployment by packaging everything into lightweight containers.
✅ You learned to manage Docker images, run containers, and create custom images using Dockerfiles.
✅ You successfully uploaded a Docker image to Docker Hub for sharing or reuse.

Related Theory – Docker
1. Introduction
Docker is an open-source tool that allows developers to build, package, and run applications inside containers.
A container includes everything an app needs — code, libraries, and dependencies — so it runs the same everywhere.
________________________________________
2. Why Use Docker
•	Works the same on any system (no “it works on my machine” issue).
•	Faster and lighter than virtual machines.
•	Easy to move and scale applications.
•	Saves time in deployment and testing.
________________________________________
3. Docker Architecture
Docker follows a client–server model:
•	Docker Client: Used to run commands like docker run or docker build.
•	Docker Daemon (Server): Runs in the background and does the actual work (building, running containers).
•	Docker Hub/Registry: Stores Docker images online.
________________________________________
4. Important Terms
Term	Meaning
Image	Blueprint or template for creating containers.
Container	A running instance of an image (the actual app).
Dockerfile	Instructions to create your own image.
Docker Hub	Cloud storage for images.
Volume	Used to save data inside containers permanently.
________________________________________
5. Container Lifecycle
1.	Create → docker create <image>
2.	Start → docker start <id>
3.	Run → docker run <image>
4.	Stop → docker stop <id>
5.	Remove → docker rm <id>
________________________________________
6. Common Docker Commands
Command	Description
docker --version	Check Docker version
docker pull ubuntu	Download an image
docker images	Show downloaded images
docker run hello-world	Run a test container
docker ps -a	List all containers
docker stop <id>	Stop container
docker rm <id>	Delete container
docker build -t myimage .	Build custom image
docker push username/myimage	Upload to Docker Hub
________________________________________
7. Advantages
✅ Lightweight and fast
✅ Same setup on all systems
✅ Easy to deploy and test
✅ Saves time and resources
________________________________________
8. Conclusion
Docker makes application deployment simple and reliable.
It allows you to package and run apps anywhere, forming an important part of DevOps and CI/CD pipelines.

Experiment 8: Implement Static Application Security Testing (SAST) using SonarQube
________________________________________
🎯 Aim:
To perform Static Application Security Testing (SAST) using SonarQube to identify code quality issues, bugs, and security vulnerabilities in a software project.
________________________________________
⚙️ Requirements:
•	Windows or Linux operating system
•	Java JDK (version 11 or above)
•	SonarQube and Sonar Scanner installed
•	A sample code project (e.g., Java, Python, Node.js)
•	Internet connection
________________________________________
📖 Theory (Easy and Precise):
Static Application Security Testing (SAST) analyzes source code without executing it.
It helps detect security vulnerabilities, bugs, and code smells early in the development process.
SonarQube is an open-source platform that automates SAST. It:
•	Scans code for quality and security issues.
•	Detects vulnerabilities (like SQL Injection, XSS, Hardcoded Secrets).
•	Provides detailed reports with remediation suggestions.
•	Integrates with CI/CD tools and IDEs.
Sonar Scanner is the command-line tool used to send your code from your local machine to SonarQube for analysis.
________________________________________
🪜 Procedure (Step-by-Step):
Step 1: Install Java
Check if Java is installed:
java -version
If not, install JDK 17 and set JAVA_HOME.
________________________________________
Step 2: Download and Install SonarQube
1.	Go to https://www.sonarqube.org/downloads/
2.	Download SonarQube Community Edition (latest LTS).
3.	Extract the ZIP file (e.g., C:\SonarQube).
________________________________________
Step 3: Start SonarQube Server
Go to the SonarQube directory → bin → choose your OS folder → run:
StartSonar.bat
Wait a few minutes until the server starts.
Now open your browser and go to:
http://localhost:9000
Login with default credentials:
Username: admin
Password: admin
(Change password when prompted.)
________________________________________
Step 4: Create a Project in SonarQube
1.	Click “Create Project” → “Manually”.
2.	Enter project name → click “Set Up”.
3.	Choose “Locally” option.
4.	Copy the Sonar Scanner command displayed on screen (you’ll use it later).
________________________________________
Step 5: Install Sonar Scanner
1.	Download from https://docs.sonarsource.com/sonarqube/latest/analyzing-source-code/scanners/sonarscanner/
2.	Extract the file (e.g., C:\sonar-scanner).
3.	Add its bin folder to your system PATH.
Verify installation:
sonar-scanner -v
________________________________________
Step 6: Create a Sample Project
Example (Java):
mkdir sonar-demo
cd sonar-demo
Add a simple Java file, e.g., App.java:
public class App {
    public static void main(String[] args) {
        System.out.println("Hello SonarQube!");
    }
}
________________________________________
Step 7: Run Sonar Scanner
Use the command generated from your SonarQube dashboard, for example:
sonar-scanner \
  -Dsonar.projectKey=sonar-demo \
  -Dsonar.sources=. \
  -Dsonar.host.url=http://localhost:9000 \
  -Dsonar.login=<your_generated_token>
________________________________________
Step 8: View Results
•	Open http://localhost:9000
•	Go to your project dashboard.
•	You’ll see a report showing:
o	Bugs
o	Vulnerabilities
o	Code smells
o	Security hotspots
o	Coverage and maintainability scores
________________________________________
💻 Program and Output:
Commands Executed:
java -version
StartSonar.bat
sonar-scanner -v
sonar-scanner -Dsonar.projectKey=sonar-demo -Dsonar.sources=. -Dsonar.host.url=http://localhost:9000 -Dsonar.login=<token>
Expected Output:
•	“Analysis successful” message in terminal
•	SonarQube dashboard displays project scan results with security ratings and issues detected
________________________________________
🧩 Result:
SonarQube successfully analyzed the source code and detected vulnerabilities, code smells, and bugs, helping improve the overall security and quality of the project.
________________________________________
✅ Conclusion:
Static Application Security Testing using SonarQube enables developers to identify and fix security flaws early in the software development lifecycle, enhancing code reliability and minimizing risks.
